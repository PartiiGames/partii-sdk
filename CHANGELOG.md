# Changelog

## 0.2.0 (unreleased)

Every SDK crate moves to 0.2.0 (one workspace version). Minor bump: new public fields and enum variants.

- `partii-net`: **room network stats** (partii's PROTOCOL.md "Network stats", `partii_net::netstats`). The hello now says `caps: ["reset", "net_stats"]` (plus `"away"` when opted in); an edge that answers with `net_stats_ms` in its `welcome` gets one small `{"t":"net_stats","v":1,"final","links":[..]}` text frame about every 30 s while the engine is in a room, and a `final: true` one just before `leave`. Per link (reported by one end only: a non-host its link to the host; in a mesh, the lower mid of two non-hosts): the path in use, time on each path, path switches, RTT p50/p95 per path from the raw pongs, each path's time to first open, WebRTC open failures, the selected candidate pair's types (web engine: read with `getStats()` when a data channel opens; native: not yet), and `stuck_ws` once for a link still on the ws relay after 30 s with no WebRTC path ever open. No addresses and no player ids. An older edge never asks, so it never gets one. Opt out with `Config { no_net_stats: true, .. }` (JSON `"no_net_stats": true`). New: `Core::on_pc_candidates(mid, path, gen, local, remote)` for drivers, `Link::take_rtt_samples`. Code that builds a `Config` literally needs `..Default::default()` (or the new field).
- `partii-net`: the **away grace** (PROTOCOL.md "Away"), **opt-in**: `Config { away: true, .. }` (JSON `"away": true` for `WebEngine`). Off by default, so a game that only bumps the SDK sees exactly what it saw before (hello `caps: ["reset"]`, the 20 s grace, `MemberSuspended` / `MemberResumed`). Opted in (hello `caps: ["reset", "away"]`), a dropped socket (a phone frozen in the background) keeps its seat for the room's `away_grace_ms` (default 30 s, 5 s to 5 min) instead of the 20 s socket grace, and comes back into the same seat on the same `conn`.
  - New events `MemberAway { mid, reason: "hint" | "dropped", until, grace_ms }` and `MemberBack { mid }` (a `reset` back restarts the reliable link, as `member_resumed {reset}` did). Opted-in engines get these **instead of** `MemberSuspended` / `MemberResumed`; those still arrive from an edge or room that sends the old frames. The ws path to an away member closes (the edge drops packets to it; reliable sends wait and go out when it's back) and its WebRTC paths restart on `MemberBack`.
  - `away()` / `back()` on `Core`, the native and web `Engine` and `WebEngine`: hint `{"t":"away"}` when the app goes to the background and `{"t":"back"}` when it returns on a socket that survived (a reconnect is back on its own). `away()`'s reply is the new `Event::AwayHeld { req, reason, until, grace_ms }`; `Core::away_hold()` reads it back. An away engine whose socket stays up past `until` gets `RoomClosed { reason: "timeout" }` (the seat is gone; join again).
  - `away_grace_ms` in `create_with` settings and `update` patches (host only).
  - Without `Config::away`, `away()` / `back()` send nothing and answer `Failed { code: "not_enabled" }`.
  - `Config` deserializes with defaults for every missing field, so `WebEngine`'s `{edge, key}` config works as documented. Code that builds a `Config` literally needs `..Default::default()` (or the new `away` field).
- `partii-net`: **sign in on a live connection** (PROTOCOL.md "Signing in on a live connection"): `auth(token: Option<String>) -> u32` on `Core`, the native and web `Engine`, `WebEngine` (`auth(token | null)`) and `bevy_partii::Rooms` sends `{"t":"auth","id","player_token"}` (`None` signs out) without reconnecting: the room code, members and links stay. Replies are the new events `Authed { req, signed_in, player_id, changed }` and `AuthFailed { req, code: AuthErrorCode, message, retry_after_ms }` (`bad_token`, `player_mismatch`, `rate_limited`, `offline`, or `Other`); auth never answers with `Failed` / `RateLimited`. On `Authed` the engine keeps the new token (or none) for every later `hello`, so resumes after a drop stay signed in; a refusal keeps the old one. `Core::player_token()` reads it.
- `partii-protocol`: `AuthErrorCode` (`BadToken`, `PlayerMismatch`, `RateLimited`, `Offline`, `Other(String)`; serializes as the wire code) and `room::auth_frame`.
- `partii-net`: room **topology**, and **star is the default**: a room created with no `topology` setting makes members link only to the host, and the host to everyone: `n - 1` peer connections instead of `n (n - 1) / 2` (a host with six phones and a guest: 7, not 28; each phone keeps 1). **Behaviour change:** a game whose non-hosts send to each other directly (member to member, or a member's `BROADCAST` meant for everyone) creates its room with `{"topology": "mesh"}` (or `Topology::Mesh.settings()`) to keep the old full mesh. The host announces the room's topology to each member over signaling (`signal` data `{"pc": "net", "topology": ..}`; older engines ignore it) and members follow it, so phones that call plain `join` need no change; members hold member-to-member links for up to `TOPOLOGY_WAIT_MS` (2 s) for it. A host on an older SDK never announces and always meshes: after the wait, a member that asked for no topology meshes with it, and one that asked for one keeps it. Nothing else on the wire changes. In a star, a member's `BROADCAST` reaches the host only, and a send to another member is dropped with one `Event::Error` per member. The host may switch with `update({"topology": ..})`. New: `Topology`, `TOPOLOGY_WAIT_MS`, `Core::topology()`, `Core::linked(mid)`, `stats()["topology"]`. The edge closes a room whose host leaves, so there is no migration; a room that names a new host rebuilds the star around it.
- `partii-protocol`: `Member.away: Option<Away>` (`{reason, until}`), `Room.away_grace_ms`, the `Away` type and `AWAY_CAP`, `DEFAULT_AWAY_GRACE_MS`, `MIN_AWAY_GRACE_MS`, `MAX_AWAY_GRACE_MS`, `AWAY_HINT`, `AWAY_DROPPED`.
- `partii-account`: **raw crash frames**. `install_panic_hook` also records the panic's stack as module + offset (≤96 frames) and each module's build id (≤24 modules: `gnu:` build-id note, `macho:` LC_UUID, `pdb:` GUID + age), and the report carries them as `frames`, `modules`, `build_id`, `main` and `arch`, so a stripped release's crash can be symbolized offline (partii's docs/CRASHES.md "Raw frames"). No new dependencies (`_Unwind_Backtrace`, `dl_iterate_phdr`, `dladdr`, `RtlCaptureStackBackTrace`); Linux, Android (64-bit), macOS, iOS and Windows; elsewhere the report is as before. They never change how partii groups a report. Needs an edge that stores them (older edges ignore them).
- `partii-account`: **the track in panic reports**. `install_panic_hook` reads `PARTII_TRACK` once (partii's docs/TRACKS.md: a track build starts with it) and stamps it into each panic at crash time, so the report's context has `track` for the build that crashed, even if the next launch (which sends it) is another. Unset, or not a track name (1-32 of `a-z`, `0-9`, `-`): no `track` key (never a null, which the edge would drop the context for). Works with today's edge (context is stored as is).
- `partii-client`: **feature flags** (`partii_client::flags`): `Flags::new(FlagsConfig { base, key, game, defaults, ranges, cache_path, .. })`, `get` / `get_bool` / `get_int` / `get_str` / `all` at once, `refresh()` (blocking, 2 s timeout, `If-None-Match` / 304, never panics or errors: offline is the disk cache, else the compiled defaults), `match_values()` for the host handshake, and the admin calls `admin()`, `override_flag()`, `clear_override()`. Only values of the compiled default's type are taken, and ints only within the flag's range (the edge's `ranges` and the game's own). The generated table has int flags' `min` / `max` on `flagsDefine`. Additive.
- `partii-client`: the referral portal (`referralsVisit`, `referralsHistory`, `referralsDashboard`; CLI `partii referrals visit|history|dashboard`) a project's Stripe dashboard link (`payoutsDashboard`; CLI `partii payouts dashboard`), and the sales of the projects a player runs as a developer (`playerProjectsEarnings`; CLI `partii earnings projects`). Additive.

## 0.1.0 (unreleased)

First public release.

- `partii-protocol`, `partii-netcode`, `partii-client`, `partii-net`, `partii-account`, `partii-content`: moved out of partii's platform repository (formerly `partii-engine` and `partii-api`).
- `partii-net::host`: a seat in a partii-host match over plain UDP (tagged packets, JOIN retries, path-probe answers). `join_with` sets how long a quiet host may stay quiet before the seat closes, so a client notices a dead host fast and asks for the match's new endpoint (partii's directory moves matches off dead hosts, at a new generation).
- `partii-server`: the `Game` trait, `export_game!` for the partii-host ABI v0.1, and `testing::Sim`.
- `bevy_partii`: Bevy 0.20 plugin.
- `partii-client`: hosted servers (`serversStart`, `serversSeat`, `serversStop`, `serversList`) and server builds (`buildsUpload` with `kind=server` and its benchmark settings). Additive.
- `partii-webrtc`, `partii-rtc`, `partii-rtc-sctp`, `partii-rtc-datachannel`: webrtc-rs 0.21 forks with game-tuned SCTP timers.
